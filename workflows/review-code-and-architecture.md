# Review Code And Architecture Workflow

## Use when

1. A meaningful code change has been made.
2. A task touches important boundaries or design decisions.
3. The owner wants architecture risk surfaced before further investment.

## Inputs

1. Project profile
2. Changed files or relevant scope
3. Architecture notes and constraints
4. Jira Epic context when delivery impact matters

## Outputs

1. Findings by severity
2. Architecture concerns
3. Proposed improvements
4. Approval-needed items
5. Residual risks

## Rules

1. Separate defects from architecture proposals.
2. Mark each architecture proposal as `required fix` or `recommended improvement`.
3. Route approval-needed items back to the owner through the primary agent.

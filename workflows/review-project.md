# Project Review Workflow

## Goal

Review a project for bugs, risks, regressions, and missing tests.

## Inputs

1. Project profile
2. Current repo state
3. Relevant config and source areas
4. Jira Epic context when delivery risk matters

## Output order

1. Findings ordered by severity
2. Open questions or assumptions
3. Residual risks or testing gaps
4. Short summary

## Rules

1. Focus on correctness and risk before style.
2. Include file references when reviewing code.
3. Mention delivery impact if a finding affects timing or scope.

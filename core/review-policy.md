# Review Policy

## Purpose

Use this policy for project reviews across data, web, and IoT work.

## Review priorities

1. Functional bugs
2. Regression risk
3. Security and privacy issues
4. Reliability and operational risk
5. Performance issues with user or delivery impact
6. Missing tests or missing validation
7. Maintainability concerns only when they materially affect delivery or risk

## Review rules

1. Prefer concrete findings over style comments.
2. Always cite evidence when possible.
3. Include file paths and line references for code findings.
4. If evidence is weak, state assumptions instead of guessing.
5. If there are no findings, say so explicitly.
6. Do not propose broad rewrites unless the current structure blocks safe delivery.

## Reporting rules

1. Findings come first.
2. Open questions and assumptions come after findings.
3. Summary comes last.
4. Keep output practical and decision-oriented.
